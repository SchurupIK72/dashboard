# Escalation To Spec

Если apply-small-fix перестаёт быть маленьким, зависимая реализация останавливается, а прогресс сохраняется — patch не теряется.

## Escalation Triggers

- нужен выбор архитектуры;
- появился новый public API, schema, protocol или migration;
- требуется больше одного логического этапа;
- ожидаемое поведение стало неоднозначным;
- изменение затрагивает несколько подсистем;
- targeted fix требует переписать тестовую инфраструктуру;
- исправление зависит от внешнего сервиса или rollout-плана.

Триггер может обнаружиться и после начала patch (например, миграция, найденная в ходе фикса) — порядок действий тот же.

## Порядок действий

1. **Остановить зависимую реализацию** — не продолжать patch молча и не «доделывать попутно».
2. **Сохранить patch и доказательства** — внесённые правки остаются в worktree, результаты проверок — в отчёте: не откатывать, не коммитить, не объявлять фикс готовым; чужие изменения не трогать.
3. **Создать отдельный draft ТЗ** — черновик в `.ai/specs/` с пометкой draft: причина эскалации, предлагаемый scope, что уже сделано. Черновик не является запуском второго workflow-шага и не означает принятие фикса.
4. **Ждать согласования пользователя** — дальнейшее планирование и реализация (включая запуск `plan-release`) идут по правилу «один шаг за сессию» и только после явного решения пользователя.

Draft не закрывает фикс: непринятый patch не объявляется готовым, ветка `fix/{slug}` не мержится, `next_skill: integrate-release` не указывается, коммита нет.

## Пример: миграция в ходе фикса

Небольшой фикс выявил необходимость миграции схемы:

- patch (уже внесённые правки) сохранён в worktree, доказательства (логи проверок) — в отчёте;
- создан отдельный draft ТЗ с причиной «обнаружена миграция схемы» и предлагаемым scope;
- фикс не закрыт: нет коммита `fix: …`, нет объявления готовности;
- молчаливое продолжение правок запрещено;
- работа возобновляется только после согласования пользователя.

## Сообщение пользователю

```markdown
Это уже не apply-small-fix: {причина}.
Patch и доказательства сохранены: {что именно и где}.
Создан draft ТЗ: {путь черновика} — причина: {эскалация}, предлагаемый scope: {1-2 предложения}.
Жду вашего решения: продолжить как ТЗ, вернуть задачу в прежние границы или отказаться.
```
