# Evals — implement-spec-stage

Regression cases; the gate before `SKILL.md` patches. Pinned: host-policy routing; 150/200 s budget; stage-local scope, no full-suite during ②; acceptance evidence standard — extended package, matrix, gate audit, evidence challenge, verdicts, nine-section report; docs acceptance reproducible without pytest; stage-level DoD gates stage close; shared rework budget; budgets hold without tests-config; disjoint test/report reservations; reopened-stage selection resolves by dependencies; consumer search by symbols and contract literals; set-based chunk reconciliation with explicit slow/UI tiers.

| ID | Invariant | Check | Failure mode |
|----|-----------|-------|--------------|
| SI-EVAL-001 | One stage per session | Several unchecked stages: only the first runs; an explicit all-stages request is the only exception | Opportunistic adjacent-stage edits |
| SI-EVAL-002 | Role files not duplicated | The skill references role files; references describe orchestration/inputs only | A role prompt copied into a reference |
| SI-EVAL-003 | Sufficiency gate before edits | `NOT_FOUND`/`INSUFFICIENT_CONTEXT`/`CHAIN_BREAK` → `references/sufficiency-gate.md`: 1–2 gaps → re-check; 3+/blocking → stop | Edits with unresolved blocking gaps |
| SI-EVAL-004 | Statuses after checks | Edits done but tests not passed → no stage `✅`, no item `[x]` | Stage marked complete before validation |
| SI-EVAL-005 | Non-main entry guard | Branch is `main`/`master` → stop with the reason | Implementation starts on main |
| SI-EVAL-006 | Wave-parallel execution | Disjoint + overlapping items, one non-code: wave plan with rationale; claude researcher → implementer → tester (researchers parallel); codex/zcode: one self-sufficient implementer per item; acceptance owner engaged per return; no overlapping `allowed_files`; codex/zcode docs/config by the same self-sufficient implementer; sequential fallback keeps semantics | Dependent items in one wave; semantics differ parallel vs sequential |
| SI-EVAL-007 | Model per complexity table | claude: simple→junior, medium→middle, complex→senior; researcher and tester ALWAYS junior; zcode: implementer/acceptor pinned GLM-5.3/max; codex: all delegated workflow roles pinned gpt-6.1-sol/low; codex: no researcher/tester sub-agent; rationale `{id}: {level} — {reason}`; user assignment wins | Ad-hoc choice; missing rationale |
| SI-EVAL-008 | Unavailable model stops work | Model or isolated sub-agent context unavailable → blocking stop, files preserved | Silent fallback; full chat history passed to a sub-agent |
| SI-EVAL-009 | Rework bounded at two returns | `failed`/formal violation → SAME implementer with the failure list; third failed check → stop and ask; author's self-fix of its own test free; `accepted` = owner `passed` AND formal check | Unlimited retries; model escalation; main agent fixing code |
| SI-EVAL-010 | Run artifacts lifecycle | Run artifacts under the `references/run-artifacts.md` layout; accepted items not re-implemented on resume; per-item item_baseline captured before assignment and item_diff isolated at acceptance are stored with the item's artifacts; only the own run directory is deleted after commit, path verified | Temp files deleted before the commit; another run's files deleted |
| SI-EVAL-011 | Workflow row tracks stages | Stage `✅`; row `🔄 (N из M)` until ALL stages `✅`; next_skill `implement-spec-stage` while stages remain, else `write-tests`; validator static field does not override | Row `✅` early; `write-tests` announced with open stages |
| SI-EVAL-012 | Validator scans stages section only | `###` outside `## Этапы реализации` → no errors; whole-document checks still apply | Valid spec failed over non-stage headings |
| SI-EVAL-013 | Acceptance tests owned per host policy | Implementer stays inside `allowed_files`, outside `tests/`; item tests (`acceptance` marker) by the acceptance owner — claude: tester; zcode: acceptor; codex: main agent; author writes nothing outside `tests/`; item→tests mapping in state | Implementer writes tests; tester edits sources; marker lost |
| SI-EVAL-014 | Wave-close suite re-run | Accumulated acceptance files (explicit paths) fail on item A → A reopens, counter continues; sibling accepted; the next dependent wave waits for acceptance AND a green accumulated stage suite | Whole wave re-implemented; counter reset; next wave on red or on acceptance alone |
| SI-EVAL-015 | Machine-readable reports | A missing required section or a placeholder phrase → rework remarks; a report over the token target is marked only — length alone is never a rework cause | Acceptance blocked on wave completion; verdicts re-derived from prose |
| SI-EVAL-016 | Test command time budget | Every sub-agent command: `timeout 150`, output to file, no pipe; surviving process >200 s = hang: kill the tree, read the file, limit never raised; slow test → `slow` marker | Waiting past 200 s; hang blamed on code; limit raised |
| SI-EVAL-017 | Stage reopened by write-tests ③ | Several `🔄` + defect registry + red proof-tests: first in record order with deps `✅` (ask only on real ambiguity); registry + red tests = the oracle; a ③ test may be adapted with reason; commit covers this stage's files, never ③ files; `✅` only with proof-tests green | Asks despite resolvable order; commits ③ files; `✅` with red proof-test |
| SI-EVAL-018 | Stage-local test scope | Every ② invocation names explicit paths/node ids: item tests + directly related existing tests; at wave close — the stage's accumulated acceptance files; full-suite runs belong to `write-tests` ③ | Bare `uv run pytest`; repo-wide marker sweep; an EXIT full-suite proof |
| SI-EVAL-019 | Host policy fixed before assignment | I1 records one policy codex/zcode/claude; codex = main-agent acceptance; zcode = implementer + exactly one independent acceptor + main-agent confirmation; claude = researcher-implementer-tester; unknown/ambiguous host blocks assignment with a stop message | Assignment started without a policy; unknown host silently run as claude |
| SI-EVAL-020 | One self-sufficient implementer per item on codex/zcode | Code AND docs/config items get a package without research_report; implementer researches/chooses/implements/checks/reworks; no separate researcher, no nested delegation, no bypass via code-mapper/data-flow-tracer; the package carries the full required-field set incl. item_baseline, list fields explicit when empty | A researcher launched for a docs item; implementer delegates research |
| SI-EVAL-021 | Implementer prohibition set on every host | Implementer never writes tests, edits spec, marks statuses, or commits; codex: main agent owns acceptance tests; zcode: acceptor owns them; step-③ roles never attached to item ② | Implementer edits tests/ or the spec; a test-writer agent added to item ② |
| SI-EVAL-022 | Claude chain preserved | Researcher-implementer-tester, mandatory research_report, sufficiency gate in I2, junior tester; claude never enters codex/zcode branches | Claude run skips research or the gate |
| SI-EVAL-023 | Implementer package completeness on codex/zcode | The implementer package carries the full required-field set incl. item_baseline, dependencies, check_commands, report_paths; list fields explicit `[]` when empty; no research_report; missing field → `INSUFFICIENT_CONTEXT: missing {field_name}` | A package without allowed_files accepted; a missing field answered from the chat history |
| SI-EVAL-024 | Self-sufficient implementer research and boundaries | The implementer reads files before editing, documents files/symbols/contracts in its Research section, chooses inside the package; a file outside allowed_files blocks dependent work until the main agent amends the package; a requirement change beyond the agreed scope goes to the user | Boundary expanded silently; an ordinary in-scope solution waits for approval |
| SI-EVAL-025 | Baseline attribution | Before assignment, record item_baseline — the dirty/untracked state of the item's area; base_commit alone is insufficient on a dirty tree; item_diff isolates only the item's changes incl. new files; foreign edits preserved, an inseparable diff blocks acceptance | A whole-tree diff attributed to the implementer; a foreign dirty diff reverted |
| SI-EVAL-026 | Implementer report contract | The codex/zcode implementer report has seven sections — Result, Research, Changed Files, Solution Summary, Criteria Mapping, Checks, Open Questions; token target 3000: over-target marked, mandatory content never truncated, details only in report_paths; no character ceiling | A missing section; a report truncated to fit; a char limit enforced |
| SI-EVAL-027 | Acceptance package extends the base set | The acceptance package adds `stage_definition_of_done`, `item_contribution`, `implementer_report`, `item_diff`, `test_directives`, `test_allowed_files`, evidence paths; criteria come from the spec — the implementer report is not the oracle; a missing criterion/contribution → acceptance blocked until the main agent amends the package | Acceptance run with a criterion/contribution missing; criteria copied from the report |
| SI-EVAL-028 | Acceptance matrix covers every mandatory criterion | Each criterion gets an independent expected result with its source, evidence (test / command / file:line), and a status PASS/FAIL/BLOCKED/N/A; an N/A needs a justification; green tests with an unproven mandatory criterion stay blocked | Matrix copied from the report; an unproven criterion silently dropped |
| SI-EVAL-029 | Formal audit gates carry evidence | F1 boundaries, F2 requirements, F3 contract compatibility, F4 applicable limits/error handling, F5 project rules, F6 check authenticity (real exit codes, no suppressed failures); every gate has evidence and a status; points never compensate a FAIL or BLOCKED gate | Gate marked without evidence; a FAIL gate outvoted by scores |
| SI-EVAL-030 | Evidence sufficiency challenge | The audit walks input → result → consumer per criterion, checks contract invariants/dependencies, gives a substantive "green check, broken promise" counterexample or justifies none; a duty deferred to another item is not required; reading dependencies beyond the diff is allowed, never expands write rights | A green component check with a broken consumer link accepted; write rights widened by reading |
| SI-EVAL-031 | Verdict follows proof, not preference | `passed` only with complete proof of all applicable mandatory criteria and gates; a PROVEN violation → `failed`; otherwise missing mandatory evidence → `blocked`; a combination returns `failed` with the blocking list enumerated; taste-level remarks never block | An advisory remark blocking a proven-complete item; a proven violation downgraded to blocked |
| SI-EVAL-032 | Acceptance report section set | Exactly Result, Acceptance Matrix, Formal Audit, Evidence Challenge, Acceptance Tests, Test Run, Failures, Advisory Notes, Open Questions; `### Result` parsed first; target 3000 tokens — over-target marked, never truncated, details only in the assigned evidence paths, no character ceiling | A missing section; a report cut to fit; raw command output pasted into the report |
| SI-EVAL-033 | Docs/config acceptance without pytest | Markdown/config item accepted via an explicit command or procedure, expected outcome up front, evidence recorded; `passed` attainable; executable code never uses this path; purely visual with no reproducible check → `blocked` | Docs item blocked for lacking pytest; code accepted via a manual look; fake coverage |
| SI-EVAL-034 | Stage-level DoD gates stage close | All items `[x]` but a mandatory stage-level link (between items or to the end consumer) unproven → stage stays open, not `✅`; BLOCKED blocks `✅`; the stage-level report records evidence and limitations; item verdicts never substitute | `✅` on item verdicts alone; broken inter-item link after close; report absent |
| SI-EVAL-035 | Shared rework budget per item | Implementer and acceptor identities with ONE shared counter: first check + default two returns; the main agent's formal remarks share the budget; third unsuccessful check → stop and ask; recreation/resume/override never reset; once the settings layer lands the count comes from the acceptance policy, never presets | Hardcoded two without provenance; formal remarks free; a fourth attempt; counter reset on relaunch |
| SI-EVAL-036 | Command budgets hold without config | ② commands name explicit paths/node ids only — item tests, related existing tests, accumulated stage acceptance; ≤ 150 s per command, surviving process at 200 s = hang, process-tree limit + pipeless log mandatory; no tests-config → defaults still hold; settings layer later supplies effective values with hang > command; full suite only in ③ | Limits cancelled without a config; pipe to console; hang ≤ command; full suite during ② |
| SI-EVAL-037 | Test/report reservations before launch | Parallel items disjoint in sources, `test_allowed_files`, AND report paths; reservations at wave planning before implementers launch, report paths at package composition; a shared editable fixture serializes its items; a dependent wave waits for acceptance + green accumulated suite | Overlapping tests/reports in one wave; reservations after launch; shared fixture edited concurrently; next wave on acceptance alone |

| SI-EVAL-038 | Native host routing | Codex uses unified workflow_implementer and explicit gpt-6.1-sol/low when named roles unavailable; all active Codex workflow/P2/release profiles use that pair; ZCode discovers two pinned native profiles; Claude tiers remain | Claude aliases or obsolete complexity profiles active on Codex; session inheritance on pinned roles |

| SI-EVAL-039 | Intermediate evidence levels | Orchestration scenarios use reproducible static contract checks; installation uses verifier fixtures; requirements map to owners and stable evidence in the release host-contract report; static checks never claim live model/API behavior | Static text checks reported as actual agent executions; pending stage DoD hidden |

| SI-EVAL-040 | S40: Python COMMENT prohibition | Tracked code and isolated literals/docstrings; ordinary/inline/shebang/encoding/pragma/noqa cases | Literals PASS; each COMMENT fails with file:line; repository PASS |

| SI-EVAL-041 | Reopened-stage selection by dependencies | Several `🔄` stages: no failure for the count itself; the first in record order whose dependencies are all `✅` is selected; none selectable → blocking issue that tells the agent to ask the user; single-stage behavior unchanged | A reopened batch blocked as ambiguous; the first reopened stage skipped despite ready dependencies |
| SI-EVAL-042 | Consumer search by symbols and literals | Consumers located by changed symbols and contract literals/selectors across source/tests/harness, not file names only; report lists applicable UI/slow/integration layers with justified exclusions; a stub at a component boundary never substitutes the consumer proof; incidental interface text is not a contract | File-name-only search; stub GREEN accepted as consumer proof; a log word treated as a contract |
| SI-EVAL-043 | Chunk reconciliation as sets | Expected set = collected unique node IDs from an explicit selection with exclusions; the union of executed IDs (retries counted once) must equal it as a set — equal totals with a missing/duplicated ID is a mismatch; timeout without summary = incomplete run; summary with unfinished teardown = registered hang; slow/UI tiers stay explicit named sets, never folded into full | Count-based reconciliation passing a swapped ID; teardown hang reported GREEN; slow tier hidden behind the word full |
| SI-EVAL-044 | Atomic stage ownership before the changing phase | I1 reserves worktree/branch/stage plus declared write scopes via `scripts/workflow_ownership.py` (policy `policies.ownership.enabled` via the shared resolver); a second claim of the same scope or intersecting scopes → CONFLICT naming owner/run, writes nothing, STOP; disjoint scopes coexist; a different worktree/clone is independent; release frees the scopes at normal completion | Second session overwrites or proceeds silently; conflict resolved by deleting the lock; worktrees blocking each other |
| SI-EVAL-045 | Stale ownership and resume keep the run's identity | mtime/PID/age alone never removes a claim — only proven completion or an explicit user decision (`break --reason completed|user_decision --proof …`); resume of the same run PRESERVES owner, evidence and rework counters, a counter never decreases; resume by another run is a CONFLICT naming the owner | Claim dropped by staleness heuristics; counters or evidence reset on resume; resume steals the scope from the live owner |
| SI-EVAL-046 | Run-dir cleanup via the deterministic tool | Own run-dir cleanup goes through `scripts/workflow_cleanup.py` (dry-run by default, explicit apply mode): referenced evidence relocated to `.ai/reports/evidence/` with references rewritten; failed/active/ambiguous runs, memory candidates, backlog and foreign trees preserved with reasons | Manual rm -rf of run trees; referenced evidence destroyed with the run dir; a failed or foreign run deleted |

| SI-EVAL-047 | One stage-level impact reporter on stage close | After the stage is ✅ and the commit exists, the main agent launches exactly one advisory reporter sub-agent — the same stage-level role on every host policy, isolated package, no nested delegation — before run cleanup; the launch itself changes no status and no counter | Reporter skipped or launched per item; a second reporter; the reporter treated as an acceptance participant |

| SI-EVAL-048 | Reporter failure stays advisory | A failed reporter or an unavailable reporter model is honestly reflected in the chat; the closed stage is never reopened, the commit, the transition, and next_skill proceed, acceptance statuses and rework counters stay untouched, no automatic relaunch or model fallback | Stage reopened or transition blocked over a report failure; the failure silently swallowed |

| SI-EVAL-049 | Reporter package isolated, built on the stage's item reports | The package carries the item wordings with linked requirements, the assigned implementer/acceptance report paths of every item, the stage-level DoD report path, summary changed_files/item_diff lists, check metrics from the reports, and the assigned impact-report path; report paths are mandatory — a package without them is rejected; the reporter writes only the impact-report path; a missing/incomplete source report shows as an honest gap, code is read only to clarify component names | The report sourced from a fresh code re-analysis; a source gap backfilled with invented effects; the reporter writing code, tests, or statuses |
