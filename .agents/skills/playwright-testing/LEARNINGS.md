# Learnings — playwright-testing

Короткие напоминания. Использовать только релевантные текущему запросу; устаревший урок заменять, а не копить противоречия.

- **`browser_snapshot` + `ref` > селекторы** — опираться на a11y-дерево и `ref`, не конструировать CSS/XPath с нуля.
- **Экономить контекст** — минимальная область snapshot (сужение только реально поддерживаемыми параметрами), console/network и скриншоты — файлами, не в контекст.
- **Гибрид визуальной проверки** — структура (snapshot) + визуал (screenshot) + точные значения (вычисляемые стили, когда инструмент есть); чистый pixel-diff даёт false positives.
- **200 ≠ identity** — порт может отвечать соседний клон/чужой процесс. До шагов браузера доказать принадлежность: свой PID, командная строка с этим worktree или маркер ревизии; недоказуемо — blocked.
- **Cleanup только свой** — останавливать/удалять только то, что создал этот запуск, перепроверив цель; чужие PID и общие базы не трогать даже при красном прогоне.
- **Неподдерживаемое — называть** — вызывать только существующие инструменты/аргументы; отсутствие capability или параметра — ограничение или blocked, не выдуманный вызов и не фиктивный PASS.
- **Статика может маскировать баг** — «у пользователя ничего, в чистом контексте работает» → эвристическое кэширование статики без `Cache-Control`; смотреть response-headers статических файлов.
- **Inventory дрейфует** — записанный перечень страниц/селекторов расходится с фактом; авторитет — живой snapshot.

## Retrieval Rules

- Прочитать в начале каждого запуска `playwright-testing`.
- Если урок вскрывает failure mode — сначала обновить `EVALS.md`, потом `SKILL.md`.
