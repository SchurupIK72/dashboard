# Token Economy

Длинная браузерная сессия расходует контекст; на больших страницах это становится узким местом. Практики снижения расхода — только инструментами, реально поддерживаемыми в сессии.

## 1. Минимальная область snapshot

Полный snapshot тяжёлой страницы возвращает большое дерево. Сужать:

- Если инструмент snapshot поддерживает параметры области (ограничение глубины дерева, поддерево конкретного элемента) — сначала верхнеуровневая структура, затем точечное поддерево (модалка, форма, таб).
- Если параметры области не поддерживаются — не передавать их: снимать snapshot только на нужных страницах/состояниях и не повторять без необходимости.

## 2. Логи — в файл, не в контекст

`browser_console_messages` и `browser_network_requests`:

- Если инструмент поддерживает запись результата в файл (аргумент имени файла) — писать напрямую: `logs/console-<page>-<ts>.log`, `logs/net-<page>-<ts>.log`.
- Если нет — сохранить вывод в файл самостоятельно; не держать длинные логи в активном контексте.
- Для быстрого «есть ли ошибки» — жёсткий фильтр уровня, остальное в файл.

## 3. Скриншоты — в файл + точечное чтение

Скриншоты сохранять в файлы каталога артефактов запуска. Для сравнения «до/после» — повторно открыть нужные файлы как изображения, а не держать оба в активном контексте одновременно без нужды.

## 4. Итеративная разведка

Не снимать всё сразу. Сначала дешёвый верхнеуровневый snapshot → определить интересующий регион → точечно углубиться. Дешевле, чем «снять всё на максимальной глубине на всякий случай».

## 5. Фильтрация network

Если инструмент поддерживает исключение статических ассетов или regex-фильтр по URL — использовать: сужает до релевантных API-вызовов. Не поддерживает — фильтровать при сохранении в файл.

## 6. Cleanup

После успешной проверки — удалять свои артефакты (`logs/`, скриншоты с префиксом запуска). Накопленные файлы не должны оставаться «на всякий случай»; оставлять только при fail/баг-репорте. Чужие файлы и каталоги не трогаются.
