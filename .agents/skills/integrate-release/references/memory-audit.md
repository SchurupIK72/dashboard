# Memory Audit

Обязательный advisory-аудит памяти навыков перед merge. Выполнение обязательно и честно; результаты — исключительно рекомендации.

## Команда

Из корня репозитория dot_ai:

```bash
python scripts/audit_skill_memory.py --version {version}
```

- Отчёт (Markdown) пишется в durable-путь `.ai/reports/memory/{version}.md` и включается в релизные артефакты; альтернативный путь задаётся флагом `--output`.
- `--json` печатает машинный отчёт в stdout (Markdown пишется только при заданном `--version`/`--output`).
- База diff — ветка `main` (переопределяется флагом `--base`); сравнивается рабочее дерево с деревом базы.
- Офлайн-токенизация использует закреплённые таблицы `assets/tokenizers/` (переопределяется `--assets-dir`).

## Пакет данных отчёта

1. **Entry diff относительно main** — добавленные/изменённые/удалённые записи LEARNINGS.md и EVALS.md каждого навыка. Запись = значимая строка файла (пункт списка или строка таблицы; заголовки и разделители таблиц не считаются). Удалённый файл виден отдельным статусом `DELETED` с его прежним содержимым в diff.
2. **Размеры и лимиты** — для каждого файла всех активных навыков (не только изменённых): размер до (в базе), после (в рабочем дереве), дельта в токенах и байтах, эффективный лимит. Лимит разрешается через `scripts/workflow_config.py`: defaults → активный preset → skills.<имя навыка>; в отчёте виден источник лимита. Превышение — advisory-замечание `OVER_BUDGET`.
3. **Tokenizer** — библиотека, закреплённая версия, encoding, установленная версия и доступность. Один tokenizer для всех файлов.
4. **Хеши** — sha256 каждого проверенного файла (текущего и базового). Сам файл отчёта исключён из хеширования и подсчёта, циклический подсчёт невозможен.
5. **Mirrors** — runtime-копии `.agents/skills/**` и `.claude/skills/**` перечисляются с указанием канонической копии `skills/<имя>/...` и признаком синхронности; они не считаются новыми уроками и не участвуют в подсчёте — счёт ведётся только по каноническим копиям.
6. **Замечания/рекомендации** — список advisory-замечаний (превышение лимита, удалённый файл памяти, рассинхрон mirror, дефект формата) или «нет замечаний».

## UNKNOWN

Если tokenizer недоступен (нет пакета, версия отличается от закреплённой, отсутствует или повреждена офлайн-таблица), размеры выводятся как `UNKNOWN` с причиной; эвристическая подмена счётчика запрещена. UNKNOWN — advisory-замечание, не ошибка выполнения.

## Пересчёт

Если после формирования отчёта менялась память (LEARNINGS/EVALS) или YAML настроек — перед merge отчёт пересчитывается повторным запуском команды. В новом отчёте фиксируются актуальные счётчики, лимиты и sha256; прежний отчёт не считается свежим.

## Порядок относительно tokenizer-preflight

Съёмка снимка параметров этим аудитом выполняется после ENTRY-preflight актуальности tiktoken. Если preflight закрепил новую версию, аудит и отчёты пересчитываются на новом pin: счётчики образуют новый baseline, история прежних отчётов не правится. Если pin не менялся — действует обычное правило пересчёта выше. Новая stable, обнаруженная повторной проверкой уже после снятия снимка, даёт `UPDATE_PENDING`: pin и снимок остаются прежними, пересчёт не требуется, merge этой гонкой не блокируется, обновление применяется в preflight следующего запуска. Недоступный официальный источник даёт `UNKNOWN` — он не называется актуальностью и не блокирует выполнение аудита; `UNKNOWN` tokenizer в самом отчёте остаётся advisory-замечанием.

## Права аудитора по памяти

Аудитор памяти (аудитор релиза или основной агент по host-политике) может сжать память сам: короче формулировки, объединение дубликатов, замена устаревшего — без потери уникального смысла и без удаления уникального урока или активного eval без согласования пользователя. Если новый состав всё ещё сверх эффективного лимита — действующий файл остаётся без изменений, кандидат сохраняется в `.ai/memory-candidates/<skill>.md`, пользователю предлагается состав или лимит; повышение лимита в `.ai/workflow.yaml` — только предложение, не самовольное изменение. Спорная смысловая правка также выносится на решение пользователя. Кандидаты не загружаются автоматически, переживают очистку run-dir и снимаются после решения. После правки памяти или YAML действует правило пересчёта выше.

## Политика блокировки

- Advisory (не блокируют merge и не дают failed функциональной приёмки): превышение лимита памяти, дефект формата памяти, смысловое замечание к содержимому, UNKNOWN tokenizer, рассинхрон mirror.
- Обязательные и блокирующие: сам запуск аудита (пропуск шага недопустим) и ошибки выполнения аудита — недоступный git/база diff, сломанный YAML (usage/реальные ошибки дают ненулевой exit).
- Функциональные проверки и остальные merge-гейты остаются блокирующими: advisory-статус памяти не ослабляет их.
