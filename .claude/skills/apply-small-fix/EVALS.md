# Evals — apply-small-fix

Regression cases. Используются как gate перед патчами SKILL.md.

| ID | Описание | Шаги воспроизведения | Ожидаемый результат | Статус |
|----|----------|----------------------|---------------------|--------|
| SF-001 | Навык должен останавливать задачу, которая выросла за пределы small-fix по содержанию | Дать задачу с миграцией, изменением схемы данных или новым публичным API (даже в 1 файле) | `apply-small-fix` не создаёт spec и не начинает patch, а направляет пользователя в `plan-release` | active |
| SF-002 | Полная постановка из Default принимается без повторного разрешения | Сформулировать полную короткую постановку (симптом/ожидаемое поведение/границы/проверка готовности) в обычном chat/default режиме, без Plan mode | навык принимает постановку и начинает работу; не требует переключения режима и не переспрашивает разрешение на уже ясное действие | active |
| SF-003 | Неполная постановка даёт предметный вопрос, не отказ по режиму | Дать «исправь быстро X» без ожидаемого поведения и критерия готовности | один предметный вопрос о недостающем поле постановки; формальный отказ из-за UI-режима отсутствует | active |
| SF-004 | Четырёхфайловый единый фикс допустим с объяснением | Дать единый локальный фикс с тестом, затрагивающий 4 файла (порог 3), с объяснением целостности задачи | маршрут остаётся `apply-small-fix`: warning о превышении порога + объяснение в отчёте, не отказ и не перевод в `plan-release` | active |
| SF-005 | Однофайловая миграция эскалируется | Попросить миграцию/изменение схемы данных в одном файле | эскалация в `plan-release` независимо от числа файлов | active |
| SF-006 | Существующая защита достаточна — новый тест не создаётся | Дать дефект, покрытый существующим тестом: на buggy-коде тест RED, после фикса GREEN | фикс проходит проверку без нового теста; дублирующий тест не пишется; в отчёте назван существующий тест и оба результата | active |
| SF-007 | Дефект без защиты — регрессионный тест пишет приёмщик | Дать дефект, не покрытый ни одним существующим тестом | регрессионный тест создаёт приёмщик (zcode — workflow-acceptance-tester, codex — основной агент, claude — tester), а не исполнитель | active |
| SF-008 | Markdown/docs-фикс проверяется без pytest | Попросить исправить формулировку или разметку markdown-файла | воспроизводимая проверка (команда или критерии и результат) зафиксирована в отчёте; full suite автоматически не запускается | active |
| SF-009 | Миграция в ходе фикса не теряет patch | Начать небольшой фикс, в ходе которого обнаруживается миграция схемы | реализация остановлена; patch и доказательства сохранены; создан отдельный draft ТЗ с причиной; фикс не закрыт (без коммита и объявления готовности); ожидается согласование пользователя; молчаливого продолжения нет | active |
| SF-010 | Конкурирующая сессия того же фикса не пишет | Вторая сессия резервирует fix-1 в том же worktree или с пересекающимися областями записи (`scripts/workflow_ownership.py reserve`) | вторая сессия получает CONFLICT с owner/run и не пишет код/тесты/статусы; ровно один владелец; независимый worktree не конфликтует | active |
| SF-011 | Владение фиксом переживает прерывание без эвристики staleness | Сессия-владелец прервана; попытка снять владение по mtime/возрасту; затем resume того же run | владение не снято по mtime/PID — только доказанное завершение или явное решение пользователя (`break --reason … --proof …`); resume сохраняет owner/evidence/счётчик rework; после принятого коммита — `release` | active |
