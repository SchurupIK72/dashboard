# Verification — apply-small-fix

Проверка фикса — воспроизведение дефекта плюс прямо связанные существующие проверки. Проверка минимальна, но убедительна; full suite автоматически не запускается.

## Состав проверки

| Шаг | Что делается |
|---|---|
| Воспроизведение | до фикса дефект воспроизводится (buggy RED): падает существующий тест, команда или зафиксированная ручная проверка |
| Прямо связанные проверки | после фикса то же самое проходит (fixed GREEN): тот же тест, та же команда, тот же критерий |
| Смежное покрытие | дополнительно запускаются только существующие проверки, прямо покрывающие изменённый код — с обоснованием связи или риска |

Соответствие «изменение → проверка»:

| Изменение | Проверка |
|---|---|
| Pure logic | targeted unit test |
| CLI/output bug | targeted command или соответствующий unit test |
| Config/template typo | render/parse check или lint |
| Docs/rules (markdown) | воспроизводимая проверка без pytest: явно названная команда (ссылка/структура/рендер) или зафиксированные критерии и результат просмотра |
| Existing regression | тест, воспроизводящий symptom |

## Существующая защита достаточна

Если существующий тест даёт buggy RED до фикса и fixed GREEN после — новый тест не обязателен и не создаётся: дублирование существующей защиты не требуется. В отчёте указывается сам существующий тест и оба его результата.

## Нет защиты

Если дефект не покрыт ни одним существующим тестом, регрессионный тест пишет приёмщик — zcode: `workflow-acceptance-tester`, codex: основной агент, claude: tester, — а не исполнитель фикса.

## Full suite

Full suite (`uv run pytest` без фильтров, весь репозиторий) автоматически не запускается: он принадлежит шагу `write-tests` (spec-маршрут) или выполняется на `integrate-release`. Дополнительные проверки сверх воспроизведения и прямо связанных допустимы только с обоснованием связи или риска и в эффективных бюджетах из `.ai/workflow.yaml`: одна команда не дольше `command_seconds` (150), выживший процесс дольше `hang_seconds` (200) — hang; лог без pipe.

## Если тесты не применимы

Docs/config допускают воспроизводимую проверку без pytest — зафиксировать её:

```markdown
Tests: not applicable
Reason: {например, исправлена только документационная формулировка}
Check: {воспроизводимая проверка: команда или критерии и результат}
```

Не использовать «not applicable» для кода, который можно проверить существующим тестом.
