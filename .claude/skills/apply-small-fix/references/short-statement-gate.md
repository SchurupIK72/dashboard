# Short Statement Gate — apply-small-fix

`apply-small-fix` запускается по короткой постановке, собранной из диалога. UI-режим (Default или Plan) не является гейтом: постановка из любого режима равнозначна.

## Required Statement Fields

Постановка должна содержать:

| Поле | Вопрос |
|---|---|
| Symptom | Что сейчас сломано или неудобно? |
| Expected behavior | Что должно стать иначе? |
| Scope | Какие файлы/зоны можно трогать и что не трогать? |
| Verification | Как понять, что фикс готов? |

Поля допускается собрать из нескольких сообщений диалога, а не только из одного формального запроса.

## PASS

- все четыре поля понятны из диалога — начинать работу, не переспрашивая разрешение на уже ясное действие;
- неясным остаётся только незначительная деталь — выбрать очевидный вариант и отметить выбор в отчёте.

## STOP

Остановиться и задать один предметный вопрос, если:

- в постановке нет симптома или ожидаемого поведения;
- нет проверяемого критерия готовности;
- задача звучит как новая функциональность, а не исправление;
- продуктовая неоднозначность не закрывается короткой постановкой — направить в `plan-release`.

STOP по режиму UI (Default вместо Plan) не является основанием для отказа.

## Prompt Back

Если gate не пройден, попросить короткую постановку:

```markdown
Симптом:
Ожидаемое поведение:
Границы изменения:
Проверка готовности:
```
