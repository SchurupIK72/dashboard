# Evals — write-tests

Regression cases. Используются как gate перед патчами SKILL.md.

| ID | Описание | Шаги воспроизведения | Ожидаемый результат | Статус |
|----|----------|----------------------|---------------------|--------|
| TW-001 | Навык должен выбирать тесты по рискам реализации, а не только по типу изменённого файла | Дать spec с завершёнными этапами, diff с domain logic, API client и pipeline wiring | `write-tests` собирает target table, выбирает слои по `test-layer-selection.md`, проверяет матрицу покрытия и sufficiency gate перед commit | active |
| TW-002 | Пороги метрик читаются только из YAML | Измерение прогона превысило мягкий порог времени | Предупреждение называет путь YAML (`defaults.budgets.testing.*`) и фактическое значение; числовые пороги не захардкожены в файлах навыка; `.ai/workflow.yaml` навыком не правится | active |
| TW-003 | История получает только завершённые прогоны | Manifest завершённого прогона (`run_status: completed`) и manifest прерванного (`incomplete`) | Строка истории добавлена только для completed; прерванный прогон остаётся диагностическим отчётом в каталоге запуска, дефекты сохранены | active |
| TW-004 | Повторное превышение мягкого порога | Тот же мягкий time-порог превышен в двух запусках подряд | Финальный отчёт содержит предложение пользователю: задача на оптимизацию или пересмотр значения YAML; навык сам значения не меняет | active |
| TW-005 | Пропуск медленного набора | Релиз не затронул модули медленного набора | Пропуск обоснован в отчёте и в строке истории; при затронутых модулях набор запускается отдельной budget-wrapped командой | active |
| TW-006 | Куратор сохраняет уникальную защиту и удаляет только доказанные дубли | Inventory из трёх acceptance-тестов: защита публичного контракта, доказуемый дубль постоянного теста, сомнительный тест | Контрактный тест продвинут (маркер снят); дубль удалён с причиной; сомнительный сохранён с объяснением сомнения; `git diff -- tests/` не содержит других правок; исходники проекта не тронуты; процентных целей сокращения нет нигде | active |
| TW-007 | Пустой inventory не запускает куратора; writer — только после принятия куратора | Прогон с пустым `grep -rl "pytest.mark.acceptance" tests/`; затем обычный прогон с inventory | Решение «куратор не запускается» зафиксировано в state file с причиной; author постоянных тестов запускается только после принятия отчёта куратора; модели ролей и бюджеты взяты из слотов `defaults.models.{host}.test_curator/test_writer` и `defaults.budgets.*`, числовых значений в пакете нет | active |
| TW-008 | Независимые дефекты собираются вместе; ошибка oracle возвращается её автору | На шаге тестирования два независимых дефекта реализации в разных пунктах и одна ошибка oracle (тест противоречит пункту) | Ошибка oracle — возврат тому же автору теста в пределах `policies.acceptance.rework_returns`, без расхода бюджета исполнителя; подтверждённые дефекты идут в реестр (stage → item → criterion → test → evidence), проверка остальных целей продолжается | active |
| TW-009 | Пакетный возврат вместо коммита; зависимый UI-шаг blocked; source не правится молча | Дефекты подтверждены в двух пунктах; UI-шаг зависит от первого дефекта; все цели проверены | UI-шаг помечен blocked со ссылкой на блокирующий дефект; `defect-report.md` в каталоге запуска; оба пункта `[ ]`, этапы `🔄`, ссылка на реестр у заголовков; строка write-tests остаётся `⬜`; коммита нет, proof-тесты и evidence сохранены без commit; `next_skill: implement-spec-stage`; возврат — полным механизмом ② с proof-тестами в пакете; счётчик доработки не сбрасывается перезапуском | active |
