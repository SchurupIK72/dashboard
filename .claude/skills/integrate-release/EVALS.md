# Evals — integrate-release

Regression cases. Используются как gate перед патчами SKILL.md.

| ID | Описание | Шаги воспроизведения | Ожидаемый результат | Статус |
|----|----------|----------------------|---------------------|--------|
| MH-001 | Навык должен различать spec и small-fix маршруты перед merge | Запустить integrate-release на ветке со spec, на `fix/*` без spec и на feature ветке без spec | Для spec проверяются этапы и archive, для small-fix archive пропускается, feature без spec получает STOP | active |
| MH-002 | Merge обязан синхронизировать project version artifacts | Запустить integrate-release на spec route с версией `v1.2.3` и найденными `pyproject.toml`, `VERSION` или `__version__` со старой версией | До merge все найденные version artifacts обновлены до `1.2.3`; при конфликте branch/spec/CHANGELOG или пропущенном файле навык получает STOP | active |
| MH-003 | Навык должен генерировать пользовательские release notes рядом с CHANGELOG | Запустить integrate-release на spec route с версией `1.2.3`, затем проверить `.ai/release-notes/1.2.3.md` | Файл `.ai/release-notes/1.2.3.md` создан, содержит `# v1.2.3 — {date}` заголовок и хотя бы одну секцию с emoji-маркером (`🆕`, `🔧`, `⚠️`, `📌`); не содержит технических деталей (`**Компоненты:**`, `**Tests:**`, paths, идентификаторы требований); версия включена в commit вместе с CHANGELOG | active |

| MH-040 | S40: Python COMMENT prohibition | Tracked code and isolated literals/docstrings; ordinary/inline/shebang/encoding/pragma/noqa cases | Literals PASS; each COMMENT fails with file:line; repository PASS | active |
| MH-041 | Перед merge навык обязан сформировать отчёт аудита памяти относительно main | Запустить `python scripts/audit_skill_memory.py --version {version}` перед merge и открыть `.ai/reports/memory/{version}.md` | Отчёт существует и содержит: добавленные/изменённые/удалённые записи LEARNINGS/EVALS относительно main (включая удалённые файлы), размеры до/после/дельту и эффективный лимит каждого файла всех активных навыков, идентичность tokenizer, sha256 проверенных файлов и mirrors с указанием канонической копии; runtime-копии не считаются новыми уроками; отчёт не хеширует сам себя | active |
| MH-042 | Замечания аудита памяти не блокируют merge | Подготовить память с превышением лимита и/или недоступным tokenizer, затем отдельный красный функциональный тест | Отчёт завершается advisory-рекомендациями или UNKNOWN с причиной и exit 0; merge и функциональная приёмка не блокируются и не получают failed только из-за содержимого памяти; красный функциональный тест продолжает блокировать merge | active |
| MH-043 | Отчёт пересчитывается после правки памяти или настроек | Изменить LEARNINGS/EVALS или YAML настроек после первого отчёта, затем повторить запуск перед merge | Повторный отчёт отражает новые счётчики и лимиты и свежие sha256; сам отчёт исключён из циклического подсчёта и хеширования; durable-копия хранится в `.ai/reports/memory/`, а не только во временном каталоге запуска | active |
| MH-044 | Носители контракта аудитора не содержат обходной блокирующий memory-гейт | Прочитать все активные шаблоны release-аудитора (product source и runtime: claude, codex, zcode) и найти в них `token_limit`, неизменяемый лимит `2500`, `estimate_tokens`, `must report no`, `compress every file over the limit`, затем найти `audit_skill_memory.py`, `.ai/workflow.yaml`, `.ai/memory-candidates/` и advisory-формулировки | Блокирующие маркеры старого контракта отсутствуют во всех носителях; лимиты памяти берутся из `.ai/workflow.yaml` через `scripts/audit_skill_memory.py` без собственного подсчёта токенов; замечания памяти advisory и не дают verdict blocked; сжатие памяти идёт по флоу кандидатов (действующий файл сохраняется, кандидат в `.ai/memory-candidates/<skill>.md`, предложение пользователю), а не принудительное на месте; отсутствие OVER не является условием завершения аудита; контент инструкции синхронен между product source и runtime каждого хоста | active |
| MH-045 | ENTRY-preflight до снимка находит новую совместимую stable | Запустить `python scripts/check_tokenizer_updates.py --report-dir .ai/reports/dependencies` до Шага 8b с fixture-источниками, где latest stable новее закреплённой версии | Вердикт UPDATE_AVAILABLE (exit 0): pin обновляется точной версией только после golden-снимка значений, provisioning, offline-проверок таблиц и совместимости Python и пересчёта памяти/отчётов; encoding и бюджеты не меняются; смена метрики даёт новый baseline без правки истории; снимок фиксируется только после зелёных проверок; красная проверка останавливает обновление, а не merge, с возвратом к прежнему pin |
| MH-046 | Новая stable найдена после снимка перед merge | Сохранить снимок (`python scripts/workflow_config.py --json`), затем запустить повторный preflight с `--snapshot` после Шага 8b | Вердикт UPDATE_PENDING (exit 0) в отчёте `.ai/reports/dependencies/`; pin и снимок не меняются посреди запуска; гонка сама по себе не блокирует merge; обновление применяется в ENTRY-preflight следующего запуска; текущая версия не называется последней |
| MH-047 | prerelease/dev/yanked пропускаются; недоступный источник даёт UNKNOWN | Запустить preflight с fixture-источниками, где «последние» — prerelease/dev/yanked, и с пустыми/недоступными источниками | pre/yanked не выбраны — вердикт CURRENT по фактической стабильной версии; недоступный источник даёт UNKNOWN (exit 2) с причиной: не «последняя», не блокирует memory-аудит и merge |
| MH-048 | Latest stable несовместим с Python запуска | Запустить preflight с fixture, где requires_python новой stable исключает интерпретатор | Вердикт INCOMPATIBLE (exit 2): обновление остановлено до решения пользователя, pin прежний, запуск продолжается; актуальность не заявляется |

| MH-049 | Разрешённый новый boundary-D регистрируется до аудита мёртвых ссылок | Подготовить release diff со ссылкой на допустимое новое продуктовое решение, запустить python scripts/find_trace_refs.py --base main, зарегистрировать решение в реестре .ai/DECISIONS.md, затем вызвать аудит чистоты | До регистрации незарегистрированный D## выводится с file:line и FAIL; после регистрации живая ссылка даёт PASS; технические ADR и чужие технические D## не создаются автоматически; локальные номера требований/чекбоксов не считаются решениями | active |
| MH-050 | Обязательный мусор и мёртвая ссылка блокируют, rationale сохраняется | Вызвать release-аудитора с diff, содержащим мёртвый D##, debug-вывод/TODO и содержательное rationale в docs, при этом applied migration не тронута | Мёртвая ссылка и обязательный мусор дают verdict blocked; comments/docs правятся механически; ценное rationale и смысл public-docs сохраняются (для кодовых файлов — перенос rationale в docs/commit); applied/hash-pinned/generated артефакты не изменяются | active |
| MH-051 | Замечания аудита, требующие изменения логики, возвращаются на реализацию | Дать release-аудитору diff с нарушением, требующим правки кодовой логики, публичного контракта или конфигурации | Аудитор не чинит логику сам: нарушение зафиксировано в отчёте и возвращено основному агенту на шаг реализации; memory-находки остаются advisory и не влияют на вердикт; после patch выполняются связанные проверки затронутых файлов | active |
| MH-052 | Установленный проект сохраняет свой реестр решений | Запустить проверку ссылок в установленном проекте с его принятым registry/path (--registry, --root) и ссылками локального формата | Кастомный реестр/путь принимаются без навязывания портального реестра; мёртвая ссылка даёт FAIL с file:line; локальные R/C-номера портала не считаются глобальными решениями; реальное новое решение вне scope не удаляется как мусор — замечание и согласование | active |

| MH-053 | Пригодное неизменённое evidence переиспользуется без полного повтора | Манифест ③ с `run_status: completed`, tested commit = текущий HEAD ветки, хеши файлов/config/lock совпадают с prospective merge-state; запустить `python scripts/validate_test_evidence.py --manifest ...` | Вердикт `reuse` (exit 0) с обоснованием; полный suite не запускается; tests diff и emoji не запрашиваются как условие | active |
| MH-054 | Version-only pin требует только затронутый targeted rerun | После ③ изменить только CHANGELOG/version artifact (version-only diff); запустить валидатор | Вердикт `targeted` (exit 1): required sets/checks ограничены version-областью; full suite не навязывается; supplement сформирован и дописывается в манифест через `scripts/test_evidence.py supplement` | active |
| MH-055 | Неизвестная область влияния требует полного набора | Изменить после ③ файл вне recorded hashes/selection/impact-map; запустить валидатор | Вердикт `full` (exit 2) с обоснованием недоказуемости границ; область не объявляется покрытой | active |
| MH-056 | Stale commit/хеши/config не дают reuse | Манифест с tested commit позади HEAD при изменённом проверенном файле; отдельно — изменённый `.ai/workflow.yaml`/lock после ③ | Изменённый проверенный файл → targeted его set'ов (не reuse); изменённый config/lock → `full`: старое доказательство не прикрывает новую конфигурацию | active |
| MH-057 | F① без ③ не требует полного набора | Маршрут small_fix без манифеста ③ с согласованным defect+related scope (`--defect-scope`); запустить валидатор | Вердикт `targeted`: воспроизведение дефекта + прямо связанные проверки; полный suite не навязывается отсутствием ③; без согласованного scope — `full` | active |
| MH-058 | Отсутствующий манифест на spec-маршруте требует полного набора | Запустить валидатор на spec-маршруте без манифеста и с путём на несуществующий файл | Оба случая — `full` (exit 2) с обоснованием отсутствия evidence; не blocked и не reuse | active |

| MH-059 | Dry-run cleanup ничего не меняет; apply удаляет только свой temp | Fixture с runs: failed (open items), current-success (terminal ✅), active sibling (активная заявка реестра); запустить `python scripts/workflow_cleanup.py --branch-slug … --run-id …` без `--apply`, затем с `--apply` | Dry-run: план перечисляет удаления/сохранения с причинами, файловая система неизменна; apply: удалён только current-success run, failed и active sibling сохранены с точной причиной; реестр ownership не изменён | active |
| MH-060 | Referenced evidence переносится с обновлением ссылок | Итоговый манифест/отчёт (`--reference`) ссылается на evidence-файл внутри удаляемого run-каталога; применить cleanup | Файл скопирован в `.ai/reports/evidence/…`, ссылка в документе переписана и разрешается после удаления исходного каталога; `policies.cleanup.preserve_referenced_evidence` читается через общий resolver | active |
| MH-061 | Orphan удаляется только при доказанном отсутствии branch/spec/ownership/resume; при сомнении сохраняется | Кандидаты `--orphans`: run без ветки и spec без активной заявки (terminal или пустой) против run с существующей веткой, с существующим spec (включая archive), с активной заявкой и с незавершённым/отсутствующим state | Первый удалён по явному перечню плана; остальные сохранены с точной причиной (branch exists / spec exists / active ownership/resume claim / non-terminal state / doubt); отдельный layout plan-release и независимость worktrees учитываются | active |
| MH-062 | Ошибка cleanup видима и не отменяет успешный merge | Вызвать `workflow_cleanup.py` с отсутствующим run-id, с run-id вне одного path-сегмента и с нечитаемым реестром ownership после успешного merge | Каждый случай — ненулевой exit с причиной, ничего не удалено; отчёт merge показывает ошибку уборки, выполненный merge не откатывается и не объявляется несуществующим | active |
