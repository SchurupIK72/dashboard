# Release Cleanliness Audit

Обязательный аудиторский проход чистоты релиза до merge: реальный вызов release-аудитора (по host-политике — субагент/профиль `workflow-release-auditor`) с явным scope, prospective diff и exemptions. Запускается только после Шага 6.5 (регистрация разрешённых D-ссылок): проверка мёртвых ссылок работает по актуальному реестру решений.

## Task-пакет аудитора

Обязательные поля (при отсутствии любого — аудитор отвечает `INSUFFICIENT_CONTEXT: missing {field_name}`, вызов повторяется после восполнения):

- **repo_root**, **branch**
- **diff_range** — обычно `main..HEAD`; prospective diff включает и несмёрженные релизные артефакты Шагов 4–7 (CHANGELOG, release notes, архив spec)
- **exemptions** — пути, которые аудитор не трогает никогда: `.ai/DECISIONS.md`, `.ai/specs/**`, `.ai/workflow-runs/**`, `tests/**`, applied/hash-pinned/generated артефакты (применённые миграции, сгенерированные снимки, lock-файлы)
- **helper_scripts** — `scripts/find_trace_refs.py` (мёртвые `D##`) и `scripts/audit_skill_memory.py` (память), оба от корня репозитория
- **report_path** — durable-путь отчёта: `.ai/reports/release-audit/{version}.md` (релизный артефакт, не временный каталог запуска)

## Зоны аудита (prospective diff, кроме памяти)

1. **Трассировка решений** — комментарии и активные docs ссылаются на решения только живыми `D##` из реестра; маркеры локальных номеров (`R##`, `C##.##`, `A##`, `X##`, «ТЗ …», «этап N») удаляются вне skills.
2. **Мёртвые `D##`** — ссылки на решения, отсутствующие в реестре. Помощник: `python scripts/find_trace_refs.py --base main` (diff-режим покрывает рабочее дерево и untracked-релизные артефакты; мёртвая ссылка — FAIL с file:line).
3. **Release-мусор** — TODO/FIXME, debug-вывод, закомментированный код, забытые временные скрипты.
4. **Изменения вне release-scope** — правки за границами согласованного объёма релиза.

## Порядок регистрации разрешённых ссылок (до аудита)

- Регистрируются только продуктовые границы; формат реестра — идентификатор `D##` первым токеном строки: `- D##: текст`, `## D## — заголовок`, `| D## | текст` или строка `D##: текст`.
- Новое реальное решение из релиза регистрируется в `.ai/DECISIONS.md` основным агентом/пользователем до аудита; технические ADR в dot_ai не создаются, чужие технические `D##` не создаются автоматически.
- Реальное новое решение вне установленного scope не удаляется как мусор: замечание в отчёте и согласование с пользователем.
- Локальные номера требований/чекбоксов портала или spec (`R##`, `C##.##`, `A##`, `X##`) не переносятся как глобальные решения и не регистрируются.
- В установленном проекте сохраняется его принятый registry/path (`--registry`/`--root` скрипта); портальный реестр не навязывается.

## Права на исправления

- Механически правится только comments/docs и гигиена памяти (LEARNINGS/EVALS): снятие чужих маркеров (смешанный `(D##/R##)` становится `(D##)`), удаление мусорных строк, сжатие формулировок без потери уникального смысла.
- Ценное rationale и смысл public-docs сохраняются: сокращение вместо удаления смысла; полезный комментарий в docs не удаляется только по признаку длины.
- В кодовых файлах dot_ai комментарии запрещены целиком блокирующим валидатором (Шаг 8a, `scripts/validate_no_comments.py`): rationale переносится в docs/commit, а не сохраняется в комментарии.
- Applied/hash-pinned/generated артефакты не правятся: их spec-ссылки остаются на месте, сдвиг фиксируется замечанием.
- Нарушения, требующие изменения кодовой логики, публичных контрактов или конфигурации, аудитор сам не чинит: замечание в отчёте и возврат на ② к основному агенту. Неавторизованный контрактный сдвиг также возвращается на ②, а не чинится на месте.

## Вердикты и блокировка

- **`clean`** — обязательное условие merge.
- **`blocked`** — подтверждённые обязательные нарушения зон чистоты (введённый мусор/debug, мёртвая ссылка после шага регистрации, изменение вне release-scope). STOP до исправления; повторный вызов аудита после правок.
- **Memory-находки — advisory**: не блокируют merge, не дают failed функциональной приёмки только из-за содержимого памяти и не отменяют Шаги 8a–8c. Ошибки выполнения самого аудита — реальные ошибки и STOP.
- Style-advisory замечания не блокируют.

## После patch

- Затронутые `.py` файлы — lint; связанные проверки каждого правленого файла; при правке памяти или YAML настроек — повторный `scripts/audit_skill_memory.py` (свежие счётчики, лимиты, хеши).
- Отчёт сохраняется в `report_path`; в отчёте — реальные exit-коды всех выполненных команд.
