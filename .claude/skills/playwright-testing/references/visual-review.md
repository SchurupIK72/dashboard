# Visual Review Rubric

Рубрика визуальной оценки. Цель — конкретный, проверяемый отчёт, а не субъективное «красиво/некрасиво».

## Принцип grounding

**Точные значения (цвета, отступы, размеры, контраст) — из DOM/CSS доступным инструментом вычисляемых стилей, не «на глаз» по скриншоту.** Screenshot — для композиции, иерархии и общего впечатления. Если инструмент вычисляемых стилей в сессии отсутствует, точные значения не заявляются: пункт рубрики отмечается как непроверенный с причиной, а не как пройденный по впечатлению.

## Рубрика оценки

### 1. Палитра/токены проекта

Дизайн-токены (палитра, отступы) брать из исходников целевого проекта. Проверять, что вычисляемые цвета ключевых блоков принадлежат токенам проекта:

- Флаг: цвет вне токенов (случайный `#...`).
- Флаг: неконсистентные оттенки между однотипными элементами.

### 2. Типографика

- `font-family` соответствует назначению (заголовки/тело — по системе проекта).
- Размеры/межстрочные читаемы, иерархия различима.

### 3. Контраст (WCAG AA)

Текст-на-фоне должен соответствовать WCAG AA (≥ 4.5:1 для обычного текста, ≥ 3:1 для крупного):

- собрать пары (color, backgroundColor) инструментом вычисляемых стилей;
- рассчитать contrast ratio по формуле WCAG и сверить с порогом;
- ratio ниже порога → проблема читаемости.

### 4. Раскладка, выравнивание, отступы

- Согласованные отступы из дизайн-системы проекта, не произвольные.
- Выравнивание сетки; элементы одной строки на одной базовой линии.
- Нет перекрытий, обрезанного текста, горизонтального скролла на десктопе (`scrollWidth > clientWidth`).

### 5. Состояния

Каждый интерактив с различимыми состояниями: `:hover`, `:focus-visible` (доступность клавиатуры), `:active`, error/invalid, disabled.

- Ловить кадрированными screenshot-ами ДО/ПОСЛЕ взаимодействия (hover/клик/фокус — доступными инструментами).
- Focus-ring обязателен для клавиатурной навигации.

### 6. Адаптив

На каждом брейкпоинте проекта (`target-inventory.md`): раскладка корректно «течёт», интерактивы доступны, скриншот на каждом размере. Инструмент viewport отсутствует → пункт непроверен с причиной.

## Сравнение изображений

Для «ожидал vs реально» — два файла-скриншота, сравнение повторным чтением изображений. Специализированные image-diff инструменты — только если они фактически есть в сессии; их отсутствие — ограничение, не препятствие к отчёту.

## Шаблон отчёта

```markdown
## Visual Review: <page> [<viewport>]

**Скриншот:** artifacts/<page>-<viewport>-<ts>.png

### Найдено
- [PASS/FAIL/NOT CHECKED] Палитра/токены: <результат grounding-проверки>
- [PASS/FAIL/NOT CHECKED] Контраст: min ratio <X>:1 (порог 4.5:1)
- [PASS/FAIL/NOT CHECKED] Раскладка: <перекрытия/скролл?>
- [PASS/FAIL/NOT CHECKED] Состояния: <focus-ring?>
- [PASS/FAIL/NOT CHECKED] Адаптив: <на каких брейкпоинтах>

### Замечания
- <конкретное наблюдение с DOM-значением или координатой>
```

`NOT CHECKED` всегда с причиной (нет инструмента вычисляемых стилей / viewport и т.п.).
