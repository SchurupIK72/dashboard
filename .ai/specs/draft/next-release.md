# Backlog следующего релиза — Dashboard

> Создан: 2026-11-24
> Файл принадлежит проекту: очистка workflow не удаляет его, повторная
> установка и upgrade dot_ai не перезаписывают.

Кандидаты для будущих релизов: симптомы, ожидания и идеи, накопленные между
планированиями. Запись здесь — не требование: навык plan-release перепроверяет
каждого кандидата по текущему коду и интервью и включает в спецификацию релиза
только явно подтверждённых кандидатов.

## Формат записи

| Поле | Содержимое |
|---|---|
| ID | Стабильный `BUG-<n>` или `FEAT-<n>`; номер — следующий свободный по счёту всех когда-либо созданных записей |
| Симптом/ожидание или польза | Для BUG: что происходит и что ожидалось; для FEAT: ожидаемая польза |
| Источник | Кто или что сообщило: диалог, инцидент, ревью, наблюдение |
| Окружение | Версия, ветка или стенд, если влияет на воспроизведение |
| Дата | Дата добавления записи, `YYYY-MM-DD` |
| Статус | `open` — ждёт проверки; `absorbed YYYY-MM-DD` — включён в спецификацию; `rejected YYYY-MM-DD` — отклонён |
| Ссылка/причина | При `absorbed` — ID требования и путь файла спецификации; при `rejected` — причина отклонения |

## Правила

- ID не переиспользуются: удаление записи не освобождает номер, новый
  кандидат получает следующий свободный.
- История не стирается молча: поглощённые и отклонённые записи остаются в
  файле с датой и ссылкой или причиной; статус меняет только plan-release
  после явного решения интервью.
- Невыбранные кандидаты остаются `open` до следующего планирования.
- Запись в этом файле не создаёт обязательства реализовать кандидата.
