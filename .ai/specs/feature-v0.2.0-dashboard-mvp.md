## Видение

Первый рабочий релиз веб-дашборда для совместного путешествия по Вьетнаму. Три пользователя (две «компании»: 2 + 1 человек) заходят по логину и паролю и видят в одном приложении:

- общие списки **покупок** и **дел**;
- **расходы** со справедливым делением чеков между компаниями, отдельными записями «корм собаки» (несёт компания-владелец) и переводами между компаниями, а также итоговый баланс «кто кому должен»;
- **погоду** для одного выбранного города;
- **курсы** RUB→VND, USD→VND, BTC и ETH (в USD и VND) с графиками за 7/30/90 дней.

Результат релиза: приложение запускается командой `docker compose up` локально или на VPS, хранит данные в SQLite в volume и не ломается при недоступности внешних источников погоды и курсов.

Вне объёма релиза: регистрация и роли, несколько валют в расходах, категории расходов, позиции внутри чека, количество и сроки у покупок и дел, push-уведомления, обновление данных в реальном времени между пользователями, постраничный вывод журнала расходов.

## Расширение решений проекта

Расширений нет. Соотнесение с IS-границами `.ai/DECISIONS.md`:

- запись «перевод между компаниями» (R26) — часть учёта взаиморасчётов («Учёт расходов двух компаний», деньги не проводятся);
- вход по логину и паролю (R12) — реализация «3 пользователя, по одному на человека» без регистрации и ролей;
- город погоды в БД (R31, R32) — часть блока «Погода».

Ответы Q3, Q4, Q9 действуют только для этого ТЗ и в `.ai/DECISIONS.md` не переносятся без отдельного подтверждения пользователя.

## Риски и ограничения

| Риск/ограничение | Влияние | Митигация |
|---|---|---|
| Контракты внешних API (currency-api с датированными значениями, CoinGecko public API, Open-Meteo) могут отличаться от ожидаемых или измениться | Нет курсов или истории, этап 6 блокируется | Исследование контрактов в начале этапов 5–6; клиенты за отдельными модулями, ответы покрыты фикстурами; ошибка источника не ломает страницы (R39) |
| Лимиты бесплатного CoinGecko (код 429) при загрузке истории и опросе каждые 15 минут | Неполная история крипты | Признак «история загружена» и повтор на следующей итерации (R37); последовательные запросы с паузой |
| Один воркер uvicorn | Ограничение горизонтального масштабирования | Допустимо для 3 пользователей; ограничение зафиксировано в R7 |
| Счётчик попыток входа хранится в памяти | Сбрасывается при перезапуске | Принято: риск низкий, 3 пользователя |
| `DASHBOARD_USERS` содержит пароли в `.env` | Утечка при публикации `.env` | `.env` в `.gitignore`, в репозитории только `.env.example` без реальных паролей |
| Cookie без `Secure` при `COOKIE_SECURE=false` по умолчанию | Передача по HTTP при запуске на VPS без HTTPS | README требует `COOKIE_SECURE=true` за HTTPS-прокси (R49) |
| Нет защиты от CSRF сверх `SameSite=Lax` | Межсайтовые POST из других браузерных контекстов | Принято: 3 доверенных пользователя; изменения только POST (R48) |
| Именованный volume скрыт от файловой системы хоста | Резервную копию БД нельзя взять копированием каталога | В README описана команда копирования файла БД из контейнера (`docker compose cp`) |
| Версия в `pyproject.toml` и CHANGELOG остаётся 0.1.0 до мержа | Рассинхронизация версий | `/health` берёт версию из `__version__` (задана в этапе 1); `integrate-release` синхронизирует `pyproject.toml` и CHANGELOG при мерже |
| Тесты и CI в проекте ещё не настроены | Нет автоматического запуска | Каталог `tests/` и фикстуры создаются на этапе 1; acceptance-тесты этапов остаются до шага `write-tests` |
| Источник фиатных курсов обновляется раз в сутки | «Текущее» значение `rub_vnd` и `usd_vnd` суточное | Показывается время получения (R36); ограничение зафиксировано в R35 |
