# Implementer package — C1.3 (read common.md in the same directory first)

role: workflow-implementer; assigned_model: sonnet (medium — connection pragmas, idempotent schema, data-integrity-adjacent); checkbox_id: C1.3
item_text: [R4] Реализовать подключение к SQLite (`foreign_keys`, WAL, `busy_timeout`) и идемпотентное применение `schema.sql`.

requirements (the oracle):
- R4: Файл SQLite создаётся по `DATABASE_URL`; схема создаётся при старте идемпотентно (`CREATE TABLE IF NOT EXISTS`); для каждого соединения включены `foreign_keys=ON`, режим WAL и `busy_timeout=5000` мс. Verification: двойной старт на одной БД без ошибок и без потери строк; `PRAGMA foreign_keys` возвращает 1, `PRAGMA busy_timeout` возвращает 5000.
- Q18/R5 context: DB lives at `/app/data` volume in Docker; WAL is used; parent directory of the DB file must be created if missing.

design guidance:
- `src/dashboard/database.py`: public `connect(path)` taking a filesystem path (`str | os.PathLike`) — creates the parent directory, opens a NEW `sqlite3` connection with `row_factory = sqlite3.Row`, executes `PRAGMA foreign_keys=ON`, `PRAGMA journal_mode=WAL`, `PRAGMA busy_timeout=5000`; `apply_schema(connection)` runs `schema.sql` (located next to the module via `Path(__file__)`) idempotently with `executescript`; optionally `open_database(path)` = connect + apply_schema. It must NOT parse `DATABASE_URL` (that is `Settings.database_path`, a sibling item).
- `src/dashboard/schema.sql`: valid SQL script. At this stage it declares no application tables (later stages append `CREATE TABLE IF NOT EXISTS …` statements to it); an empty file (one newline) is acceptable; it must be included in the package directory so Docker can copy it. Never put SQL comments narrating the spec.
- Connection per use (no global connection). Calling `apply_schema` twice on the same DB must not raise or drop data.
- No `Any`, full type hints, no comments except `D##`, one-sentence docstrings on public API at most.
